# Jev 시연 3종 심층 가이드

조사·점검일: 2026-09-26. 여기서 “세 가지”는 이 프로젝트에서 준비한 **Jev-Router**, **Jev-Pruner**, **Fast-Jev-Compaction**을 뜻한다. 각 저장소의 현재 README와 판단·훅 코드를 기준으로 정리했다. 현재 셸에서 라이브 API 실행은 하지 못했으므로, 아래의 기대 장면은 구현에서 도출한 **관찰 기준**이지 실측 결과가 아니다.

## 세 시연이 말하는 것

| 시연 | 루프의 위치 | Jev의 질문 단위 | 실제로 바꾸는 주체 | Claude Code | Codex |
| --- | --- | --- | --- | --- | --- |
| Router | 새 사용자 턴 첫 모델 요청 | 작업 난도 점수 3개 + 사용 가능 모델 중 Choice | 로컬 프록시의 모델 요청 재작성 | `jev-claude` 프록시 | `jev-codex` 프록시 |
| Pruner | Bash 명령 완료 후, 결과가 모델에 들어가기 전 | 긴 stdout의 청크마다 Noul | 출력 교체 훅 또는 명시적 래퍼 | `tool.call` function hook | `$jev-pruner` 명시적 래퍼. 일반 셸은 그대로 |
| Compaction | 누적 대화 정리 시점 | 오래된 도구 호출마다 `keepCall`, `keepResult` Noul | `session.compact` 훅 또는 라이브러리 호출자 | 원본 자동/수동 컴팩션 훅 | 원본 자동 훅 없음. JSON 기록에 라이브러리 별도 적용 가능 |

이 셋은 “Jev를 붙인다”는 공통점이 있지만 **자동 적용 범위가 같지 않다**. 발표에서 동일한 그래프를 그리되, 이벤트·후보·실행 권한을 각각 다르게 표시한다. [Router README](https://github.com/gargpratyush/jev-router#how-it-works), [Pruner README](https://github.com/tamaratran/jev-pruner), [Compaction README](https://github.com/tamaratran/fast-jev-compaction).

```mermaid
flowchart LR
  U[사용자 새 턴] --> R[Router: 모델 선택]
  R --> M[코딩 모델과 도구 루프]
  M --> O[긴 Bash 출력]
  O --> P[Pruner: 출력 청크 선택]
  P --> H[대화 기록 누적]
  H --> C[Compaction: 오래된 호출·결과 선택]
  C --> M
```

핵심 멘트: “Jev가 모델을 실행하거나 로그를 지우거나 기억을 요약하는 것은 아닙니다. 정해진 후보에 확률을 주고, 프록시·훅·래퍼가 임계값과 예외를 적용합니다.”

## 1. Jev-Router — 이번 턴을 어느 모델에 맡길까

### 실제 동작

대상 구현은 [gargpratyush/jev-router](https://github.com/gargpratyush/jev-router) npm `0.3.0`이다. `jev-claude`/`jev-codex`가 각각 실제 CLI를 실행하고 루프백 프록시를 사이에 둔다. Claude Code는 `ANTHROPIC_BASE_URL`, Codex는 임시 사용자 정의 provider를 이용한다. 사용자가 `/model`에서 구체 모델을 고르면 라우팅을 멈추고 그대로 통과시키며, `jev-router`를 선택하면 다시 켠다. 새 사용자 턴 첫 요청에서만 판단하고, 이어지는 도구 루프는 그 턴의 선택을 유지한다. [README의 인터페이스·프록시 설명](https://github.com/gargpratyush/jev-router#how-it-works).

Jev 요청의 state는 **현재 프롬프트, 현재 모델, 추정 컨텍스트 토큰 수, 계정의 사용 가능 모델 ID**다. 질문은 전체 작업 난도·추론 필요도·도구 복잡도의 Score 셋과 실제 모델 후보 Choice 하나다. 저장소는 그 응답을 그대로 실행하지 않고 [policy.mjs](https://github.com/gargpratyush/jev-router/blob/master/src/policy.mjs)에서 적용한다. 점수 셋은 설명용 지표이고, 최종 모델 선택은 Choice와 정책의 결과다. [config.mjs](https://github.com/gargpratyush/jev-router/blob/master/src/config.mjs), [router.mjs](https://github.com/gargpratyush/jev-router/blob/master/src/router.mjs).

정책에서 중요한 네 갈림길:

1. 프롬프트에 `use opus`처럼 명시적 모델/티어 요청이 있으면 사용자의 선택이 우선한다.
2. Jev 실패·시간 초과·인식 불가능한 응답이면 현재 모델을 유지한다. 요청당 1.5초, 전체 3초의 기한과 제한된 재시도가 코드에 있다.
3. confidence가 0.3 미만이면 하향 전환하지 않고, 상향도 balanced 수준으로 제한한다. 이 confidence는 정답 확률로 말하지 않는다.
4. 컨텍스트가 약 20,000토큰을 넘으면 하향 전환을 막아 프롬프트 캐시 재생성 비용을 피한다. 해당 티어가 사용 불가하면 가능한 쪽으로 보정하며, 장기/고비용 티어는 별도 opt-in이다.

이 구현의 “절약”은 **항상 싼 모델을 고르는 것**이 아니라, 실패하거나 불확실할 때 현재 모델을 유지하면서 충분한 모델을 찾으려는 정책이다. 따라서 두 프롬프트가 다른 티어로 가리라는 보장은 없다. README의 기본 티어-모델 표도 계정 모델 목록과 버전에 따라 달라진다. [정책 코드](https://github.com/gargpratyush/jev-router/blob/master/src/policy.mjs), [README의 Routing policy](https://github.com/gargpratyush/jev-router#routing-policy).

### 이 프로젝트에서의 시연

[router-demo](router-demo/README.md)는 전역 `jev-claude` 명령을 요구하지 않고 npm 로컬 의존성의 원본 bin을 실행한다. 두 CLI를 Seminar 루트에서 시작한다.

```sh
cd 2026-09/router-demo
npm install
npm run doctor
npm run claude
# 다른 터미널에서: npm run codex
```

같은 파일 읽기 요청을 두 셸에 보낸다. 첫 요청은 “`2026-09/시연-그래프.md`를 읽고 제목 한 줄만 말해줘. 수정하지 마.”, 두 번째는 “`2026-09/context-demo/scripts/run.mjs`의 실패 시 원문 보존 경로와 최종 성공 판정 사이에 빠진 경우가 있는지 조사해줘. 수정하지 마.”처럼 **실제 프로젝트 자료를 대상으로 하되 읽기 전용**으로 한다. 발표자는 쉬움/어려움의 정답 티어를 사전에 약속하지 않는다.

보여줄 증거는 `요청 → Jev 권장 모델/지표 → 정책 사유 → 실제 선택 모델`이다. Claude Code의 상태선과 `/jev-explain`, Codex의 `[Jev]` 코멘터리와 `$jev-explain`을 확인한다. 설명 기능은 마지막 라우팅 때 저장한 요청·응답을 읽으며 재점수하지 않는다. 수동 모델 선택, 키 없음, 시간 초과를 각각 별도의 **정책 분기**로 설명할 수 있다. [설명 기능](https://github.com/gargpratyush/jev-router#claude-code-interface).

### 주의할 주장

- “Claude Code/Codex 자체 기능”이 아니다. 외부 프록시가 두 CLI의 요청 형식을 다룬다.
- “Jev가 전체 저장소를 보고 모델을 고른다”가 아니다. 요청에는 **사용자 프롬프트와 현재 모델·컨텍스트 크기·사용 가능 모델 ID 같은 메타데이터**가 들어가지만, 저장소 파일 전문이나 이후 도구 결과는 라우팅 판단에 넣지 않는다. [요청 구성 코드](https://github.com/gargpratyush/jev-router/blob/master/src/router.mjs).
- 사용자 요청의 문구가 외부 서비스로 간다. 비공개 정보가 든 프롬프트는 시연에 쓰지 않는다.
- 원본 README가 밝힌 검증 환경은 Windows의 Claude Code 2.1.101/Codex 0.154.0이다. 현재 로컬은 Claude Code 2.1.283/Codex 0.157.1이므로 프록시 호환성은 행사 전 라이브 확인이 필요하다. [Limitations](https://github.com/gargpratyush/jev-router#limitations).

## 2. Jev-Pruner — 방금 나온 긴 출력에서 무엇을 남길까

### 실제 동작

대상 구현은 [tamaratran/jev-pruner](https://github.com/tamaratran/jev-pruner)다. Claude Code의 `tool.call` 훅은 Bash 명령의 실행 결과를 받은 **후**, 모델이 보기 **전**에 stdout을 교체할 수 있다. 원본 [훅 코드](https://github.com/tamaratran/jev-pruner/blob/main/hooks/fast-jev-output.ts)는 `next(event)`로 실제 명령을 먼저 실행하고, 오류·거부·짧은 출력·문서형 결과 등은 그대로 반환한다.

진입 문턱은 **추정 10,000토큰 초과**이며, 사용자가 `minTokens`를 올릴 수 있지만 그 아래로 낮출 수는 없다. 기본 청크는 20줄, 최대 200개로 합친다. 전체 대화 기록·명령·출력 청크를 state에 넣고 각 청크에 “남겨야 할 줄이 하나라도 있는가?”라는 Noul을 묻는다. 한 청크에 단 한 줄이라도 필요하면 청크 전체를 보존한다. 히스토리가 길면 여러 구간으로 나누어 평가하며 어느 구간이든 keep이면 보존한다. [출력 엔진](https://github.com/tamaratran/jev-pruner/blob/main/src/output.ts), [히스토리 분할](https://github.com/tamaratran/jev-pruner/blob/main/src/history.ts).

Jev의 낮은 점수만으로 바로 제거하지 않는다. 첫/마지막 청크, 인식된 오류·경고·테스트 총계·결과·아티팩트 경로와 주변 줄, 필요 여부가 불확실한 줄, 모든 히스토리에 대해 끝까지 점수화하지 못한 청크는 남긴다. 실제 제거에는 keep 점수가 기본 임계값 0.5보다 낮고 **0.1 이하**여야 한다. JSON/XML/YAML/diff와 원문 문서·소스 코드, `cat`/`git diff` 같은 전체 문서 명령은 통째로 보존한다. 즉 “모든 긴 로그를 절반으로 자른다”가 아니라 **명백한 반복 진행 로그만 보수적으로 생략**한다. [README의 보존 규칙](https://github.com/tamaratran/jev-pruner#information-retention-rules), [출력 엔진](https://github.com/tamaratran/jev-pruner/blob/main/src/output.ts).

가지치기가 성공하면 `[N lines omitted]`와 원본 아카이브 경로가 표시된다. Claude 플러그인은 프로젝트의 `.claude/fast-jev-output/`을 사용한다. Codex 래퍼는 프로젝트의 `.jev-pruner/`에 원본을 보관한다. 민감정보로 보이는 명령·출력은 아카이브하지 않는 예외가 있다. 아카이브 쓰기·Jev 요청·안전한 출력 예산 확보에 실패하면 원본 결과를 돌려준다. [Claude 훅](https://github.com/tamaratran/jev-pruner/blob/main/hooks/fast-jev-output.ts), [Codex 동작 설명](https://github.com/tamaratran/jev-pruner#how-the-codex-wrapper-works).

Codex는 원본 구현 기준 **일반 셸 결과를 자동 교체하지 않는다**. `PreToolUse` 훅은 기록 위치를 잡고, 실제 실행은 `$jev-pruner`가 명시적 명령 래퍼를 통과시켜야 한다. 비대화형 명령이 대상이며, 실패 종료·비정상 UTF-8·자격증명 의심 출력 등은 원문 통과한다. 원본 저장소가 검증한 Codex CLI는 0.152.1이다. 현재 로컬 0.157.1에서 같은 경로가 작동하는지는 확인 전이다. [Codex 절차](https://github.com/tamaratran/jev-pruner#codex).

### 이 프로젝트에서의 시연

[context-demo](context-demo/README.md)의 `print-noisy.mjs`가 공개 합성 빌드 로그 약 20.9만 자를 만든다. 반복 `cache entry` 가운데 `BUNDLE Q7 = sha256:7e4c9a`, `ROLLBACK TARGET = stable-snapshot`, 최종 성공 문장이 있다. 두 정확한 값은 **손실 여부를 확인할 기준**이지 Jev에게 정답을 알려주는 성능 점수가 아니다.

Claude Code에서는 이 프로젝트의 `npm run claude`로 원본 플러그인 두 개를 로드한 후 “`node 2026-09/context-demo/scripts/print-noisy.mjs`를 한 번 실행하고 두 값을 보고하라”고 요청한다. Codex에서는 원본 플러그인을 빌드·등록하고 새 세션에서 `/hooks`를 확인한 뒤 `$jev-pruner`를 명시해 같은 명령을 실행한다. 설치·키·네트워크 경로는 [context-demo README](context-demo/README.md)에 있다.

성공 화면은 **`trimmed=true`(라이브러리 보고서) 또는 생략 마커(에이전트 화면)**로 가지치기를 확인하고, 여기에 **두 값의 정확한 보존과 원본 복구 경로**까지 확인해야 한다. 단지 명령이 성공했거나 답이 짧아졌다는 것은 Pruner 작동 증거가 아니다. 실패하면 원본을 유지한 이유(문턱 미달, 문서형 출력, 키/네트워크, 예산 부족)를 표시한다.

### 주의할 주장

- 출력만 바꾸며 명령 실행 자체를 생략하거나 권한을 우회하지 않는다.
- 저장소 README에는 모델에 안 보이는 반복 로그가 아카이브에 남을 수 있다. “영구 삭제”라고 부르지 않는다.
- TypeSafe에는 출력 청크뿐 아니라 현재 대화의 일부/전체 구간과 도구 인자가 들어갈 수 있다. 공개 픽스처만 시연에 사용한다.
- 아카이브가 있더라도 안전하지 않은 생략을 정당화하지 않는다. 원본 코드는 불확실하거나 완전히 점수화되지 않은 내용을 보존한다.

## 3. Fast-Jev-Compaction — 오래된 도구 기록을 어떻게 줄일까

### 실제 동작

대상 구현은 [tamaratran/fast-jev-compaction](https://github.com/tamaratran/fast-jev-compaction) npm `0.2.0`이다. 원본 Claude Code 플러그인은 실험적 function hook의 `session.compact`에 연결된다. 자동 경로는 턴 완료 후 컨텍스트 사용률이 기본 60% 이상일 때 컴팩션을 요청하고, 수동 `/compact`도 같은 훅을 통과한다. [훅 코드](https://github.com/tamaratran/fast-jev-compaction/blob/main/hooks/fast-jev.ts).

라이브러리는 `tool_use_id`로 도구 호출과 결과를 짝짓는다. 첫 메시지와 최근 기본 6개 메시지의 호출은 고정한다. 그 밖의 각 호출마다 `keepCall`과 `keepResult` 두 Noul을 묻는다. Jev에 보낼 state는 대화를 오래된 순서로 담지만, 큰 도구 결과의 전문은 길이 안내로 바꾸고 크기 제한에 맞춰 단계적으로 압축한다. **최종 출력에서는 사용자·어시스턴트의 일반 텍스트를 고치거나 요약하지 않는다.** 판단 대상은 짝지은 도구 호출과 결과다. [README의 알고리즘](https://github.com/tamaratran/fast-jev-compaction#how-it-works), [호출 수집 코드](https://github.com/tamaratran/fast-jev-compaction/blob/main/src/state.ts).

기본 keep 임계값은 0.5다. `keepResult ≥ 0.5`이면 호출·결과를 모두 유지한다. 결과 점수는 낮지만 `keepCall ≥ 0.5`이면 호출은 남기고 결과를 앞부분과 재실행 안내로 축약한다. 둘 다 낮으면 호출과 결과를 **함께** 제거한다. 결과만 홀로 남지 않도록 구성한다. 최근 고정 메시지는 Jev 판단으로 제거되지 않는다. [결정·재구성 코드](https://github.com/tamaratran/fast-jev-compaction/blob/main/src/compact.ts).

Claude 훅은 결과 문자 수가 기본 **25% 이상 줄지 않으면 내장 요약 경로로 복귀**한다. 키 없음, 네트워크/응답 오류, state가 예산에 안 맞는 경우도 내장 요약으로 돌아간다. 따라서 “요약을 전혀 쓰지 않는다”는 말은 **Jev 경로가 채택된 턴에만** 맞다. 라이브러리 단독 호출자는 실패·절감 부족 시 어떻게 할지 직접 정해야 한다. [훅의 폴백 분기](https://github.com/tamaratran/fast-jev-compaction/blob/main/hooks/fast-jev.ts).

원본 플러그인의 자동 `session.compact` 연결은 Claude Code용이다. Codex에도 같은 개념을 적용할 수 있지만, 이 저장소를 설치하기만 하면 Codex 기록이 자동 컴팩션되는 것은 아니다. [context-demo](context-demo/README.md)는 **원본 라이브러리를 합성 JSON 대화에 직접 호출**해 Codex에서도 설명 가능한 알고리즘 시연을 제공한다. 이것과 Codex 네이티브 세션의 자동 변경은 분리해서 말해야 한다.

### 이 프로젝트에서의 시연

Pruner 이후 빌드 결과를 `Bash` 도구 결과로 넣은 대화 기록을 만든다. 앞에 놓인 오래된 임시 스캔 `t1`과 빌드 결과 `t2`가 서로 다른 보존 가치를 갖도록 했다. `context-demo`의 `npm run demo:live`는 **두 원본 라이브러리를 순서대로 호출**하고 `output/transcript-before.json`, `transcript-after.json`, `report.json`을 남긴다. 실제 Jev 결과의 `decisions`에서 각 호출의 행동(`keep`, `drop_result`, `drop_call`)과 두 정확한 값의 보존을 읽는다.

`npm run demo`는 네트워크 없는 예행연습용으로 Jev 대신 **명시적으로 고정된 가짜 점수**를 반환한다. 이 수치는 발표에서 Jev 결과·성능·정확도로 쓰지 않는다. Claude Code 라이브 화면에서는 충분한 기록 후 `/compact`를 실행하고 `kept … no summary`인지 `fallback to built-in summary`인지 그대로 보여준다. 짧은 세션이면 후보가 적거나 25% 절감 기준에 못 미쳐 폴백하는 것이 자연스럽다.

### 주의할 주장

- 텍스트를 요약하지 않지만 오래된 도구 결과를 제거하므로 **무손실 압축은 아니다**. 필요한 사실이 사라질 가능성을 손실 검사용 값과 원문 재조회로 확인한다.
- Jev에 전송되는 state에는 사용자·어시스턴트 텍스트와 도구 입력이 포함된다. 출력 전문은 기본적으로 짧은 안내로 치환되지만, 대화의 민감한 문장이 외부로 나갈 수 있다.
- 토큰 수는 추정치다. `charsBefore → charsAfter`를 API 비용 절감률이나 답의 정확도 향상으로 바꾸어 말하지 않는다.
- 원본의 SwiftUI 애니메이션 데모는 각본형이며 API를 호출하지 않는다. 보여준다면 “설명용 재현 화면”으로 표시한다. [README의 Animated demo](https://github.com/tamaratran/fast-jev-compaction#animated-demo-macos).

## 세 가지를 한 발표로 묶는 법

15분 세션 2에서 세 구현을 모두 라이브로 구동하면 설치·인증·네트워크 변수가 많다. **개념 순서는 Router → Pruner → Compaction**이 좋다. 사용자 턴 시작, 도구 결과 수신, 기록 정리라는 시간 순서이기 때문이다. 다만 실측 화면은 각 단계별로 분리해 보관한다. Router의 프록시와 Claude의 두 function hook을 한 세션에 동시에 얹는 조합은 이 프로젝트에서 검증하지 않았고, 그 상태를 “통합 동작”이라고 주장하지 않는다.

| 장면 | 권장 화면 | 관객에게 확인시킬 한 가지 |
| --- | --- | --- |
| Router | 같은 요청의 CLI 상태선/코멘터리와 설명 카드 | Jev 권장과 최종 모델이 다를 수도 있다는 정책 |
| Pruner | 원본·가지친 로그 나란히, 두 값 검색 | 긴 로그를 삭제하지 않고 필요한 줄과 복구 경로 유지 |
| Compaction | 전후 JSON의 호출 목록과 결정표 | Pruner 후에도 기록을 다시 평가하며 텍스트는 요약하지 않음 |

세 구현 모두 Jev가 실패하면 기존 경로를 계속 쓰도록 설계되었다. 하지만 **폴백의 의미는 다르다**: Router는 현재 모델 유지, Pruner는 원본 출력 유지, Compaction 훅은 Claude 내장 요약 사용이다. 이 차이를 발표의 결론으로 삼으면 세 사례가 단순 설치 소개로 끝나지 않는다.

## 현재 준비 상태와 완료 조건

현재 이 작업공간에는 [router-demo](router-demo/README.md)와 [context-demo](context-demo/README.md) 실행 구조·합성 픽스처가 있다. 로컬에서 Node 24.18.0, Claude Code 2.1.283, Codex CLI 0.157.1은 확인했다. 그러나 `JEV_API_KEY`/`TYPESAFE_API_KEY`가 없고 npm 레지스트리 DNS가 차단되어 원본 패키지가 설치되지 않았다. Orca를 통한 대화형 터미널 제어도 이전 점검에서 샌드박스에 거부됐다. **따라서 세 시연의 라이브 성공, 지연 시간, 실제 모델 선택, 실제 제거율은 아직 미측정**이다.

행사 전에는 키가 있는 네트워크 환경에서 각 구현을 **별도 세션**으로 예행하고 다음을 기록한다.

1. 버전, 프롬프트/명령, 시작 모델, 훅·래퍼 활성 여부.
2. Jev 판단값과 코드 정책의 최종 행동. Router는 실제 모델, Pruner는 생략 마커·원본 경로, Compaction은 결정표·폴백 토스트.
3. 손실 검사용 값 두 개의 최종 보존 여부. 실패했다면 성공 화면으로 쓰지 않는다.
4. 키·개인정보·전체 프롬프트가 노출되지 않게 가린 화면 녹화. 녹화본은 라이브 결과로 소개하지 않는다.

이 문서의 저장소별 설명은 위에 연결한 **원본 README·소스 코드**에 근거한다. 모델/CLI 버전과 훅 API가 바뀌면 행사 직전에 같은 경로를 다시 확인한다.
